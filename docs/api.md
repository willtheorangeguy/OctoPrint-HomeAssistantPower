# API

The plugin exposes OctoPrint's authenticated Simple API at `/api/plugin/homeassistant_power`. Start with GET for a status snapshot. Commands use POST with a JSON `command` field. The plugin also consumes Home Assistant's REST API from the server; it does not expose your Home Assistant token through this endpoint.

## Authentication and request setup

Use an OctoPrint API key with the permissions listed below. This key is separate from the Home Assistant token saved in plugin settings. OctoPrint documents the routing and command contract in [SimpleApiPlugin](https://docs.octoprint.org/en/main/plugins/mixins.html#simpleapiplugin).

Start an interactive Python session in an environment with `requests`, then paste this setup once. It prompts for your actual server and key without storing either in source. The following examples run in that same session.

```bash
python
```

```python
from getpass import getpass
import requests

octoprint_url = input("OctoPrint base URL: ").strip().rstrip("/")
octoprint_key = getpass("OctoPrint API key: ")
endpoint = octoprint_url + "/api/plugin/homeassistant_power"
headers = {"X-Api-Key": octoprint_key}

def command(name, **parameters):
    response = requests.post(
        endpoint,
        headers=headers,
        json={"command": name, **parameters},
        timeout=15,
    )
    response.raise_for_status()
    return response.json()
```

The example entity `switch.printer_plug` comes from the plugin's settings and tests. Substitute an entity saved in your installation. Switching examples change that physical entity's power state.

## Status and error conventions

| Condition | Response |
| --- | --- |
| Successful plugin handler | HTTP 200, JSON described below. |
| Home Assistant request failure or caught handler exception | Usually HTTP 200 with `{"ok": false, "error": "..."}`. Inspect JSON even after HTTP success. |
| Missing required plugin permission | HTTP 403, generated by OctoPrint/Flask; not guaranteed to be JSON. |
| Unauthenticated request | Rejected by OctoPrint before the protected API handler. |
| Invalid command or missing required command parameter | OctoPrint Simple API validation rejects the request; unknown commands return HTTP 400. |
| Printer off needs confirmation | HTTP 200 with `ok: false` and `needs_confirmation: true`. |

`refresh` returns a snapshot without an `ok` flag; inspect its `error` field. A successful asynchronous command means the worker accepted the action, not that power or serial state has already changed.

## GET status

`GET /api/plugin/homeassistant_power` requires `STATUS`. It reads the cached state and does not force a Home Assistant poll. There are no plugin-specific query parameters.

```python
response = requests.get(endpoint, headers=headers, timeout=15)
response.raise_for_status()
print(response.json())
```

An example JSON snapshot for a configured printer after startup:

## Switching commands

All commands in this section require `PLUGIN_HOMEASSISTANT_POWER_CONTROL`. `entity_id` must match a saved entity row. `show_in_navbar: false` does not revoke access.

### Turn on

POST body fields: `command: turn_on`, required string `entity_id`.

```python
print(command("turn_on", entity_id="switch.printer_plug"))
```

```json
{"ok": true}
```

The service is `<entity-domain>.turn_on`. A missing configured entity or Home Assistant failure returns `ok: false` with an error.

### Turn off

POST body fields: `command: turn_off`, required string `entity_id`, optional boolean `force` (default `false`). This sends a manual off request without cooldown.

```python
print(command("turn_off", entity_id="switch.printer_plug"))
```

When the selected printer is actively printing, the response is:

```json
{
  "ok": false,
  "needs_confirmation": true,
  "error": "A print is running on this printer."
}
```

After obtaining explicit confirmation from your own client user, repeat with `force=True`. Do not implement unconditional automatic retry with force. When switching is allowed and the service succeeds, the response is `{"ok": true}`.

The server checks `is_printing()`, not `is_paused()`. The row's `confirm_off` value is enforced only by the bundled browser UI.

### Toggle

POST body fields: `command: toggle`, required string `entity_id`, optional boolean `force` as for turn-off.

```python
print(command("toggle", entity_id="switch.printer_plug"))
```

```json
{"ok": true}
```

If the cached state is `on`, the plugin uses the guarded turn-off handler. Otherwise it sends turn-on. It does not call Home Assistant's toggle service, and the decision can reflect a stale poll. Confirmation and error responses are the same as the corresponding switching handler.

## Power on printer

POST body: `{"command": "power_on_printer"}`. Requires plug-control permission. Uses the saved `printer_entity`, `auto_on.auto_connect`, and `auto_on.connect_timeout`; there are no required parameters.

```python
print(command("power_on_printer"))
```

```json
{"ok": true}
```

`ok: true` means the worker started. An already-busy worker returns `{"ok": false}`. An empty printer selection returns `{"ok": false, "error": "No printer entity is configured in the settings."}`. Later worker outcomes are reported through plugin messages.

## Cancel auto-off

POST body: `{"command": "cancel_auto_off"}`. Requires plug-control permission. No parameters.

```python
print(command("cancel_auto_off"))
```

```json
{"ok": true}
```

True means a cancellation request was set for an active controller. An idle controller returns false. Cancellation does not retract a service call already being issued; see [Usage](usage.md#post-print-power-off).

## Refresh

POST body: `{"command": "refresh"}`. Requires plug-control permission. No parameters.

```python
snapshot = command("refresh")
print({"printer_entity": snapshot["printer_entity"], "error": snapshot["error"]})
```

Example projection of the response:

```json
{"printer_entity": "switch.printer_plug", "error": null}
```

The complete response has the same shape as [GET status](#get-status), after a synchronous poll attempt. On a Home Assistant polling failure, `states` is empty and `error` contains the message. It has no `ok` field.

## Settings commands

These three commands require OctoPrint `SETTINGS` permission. Each can receive `base_url`, `access_token`, and `verify_certificate` to test unsaved dialog values. A nonempty `base_url` creates a temporary client; a missing/empty token then falls back to the saved token, and certificate verification defaults to true. With an empty base URL, the saved client is used. The request timeout comes from saved settings.

### Test connection

Required POST fields are `command: test_connection`, string `base_url`, string `access_token`, and boolean `verify_certificate`. Empty URL and token strings allow this example to use saved credentials:

```python
print(command("test_connection", base_url="", access_token="", verify_certificate=True))
```

```json
{"ok": true, "message": "API running."}
```

The client checks Home Assistant's `/api/` greeting. A failed connection or unexpected greeting returns `ok: false` and `error`.

### List entities

POST body: `{"command": "list_entities"}`. Connection overrides are optional; there are no required parameters.

```python
print(command("list_entities"))
```

Example with one switch and one sensor:

```json
{
  "ok": true,
  "controllable": [{"entity_id": "switch.printer_plug", "name": "Printer Plug"}],
  "sensors": [{"entity_id": "sensor.printer_plug_power", "name": "Printer Plug Power", "unit": "W", "device_class": "power"}]
}
```

The response lists all discoverable Home Assistant entities, not only saved rows. The controllable domains are `switch`, `light`, `input_boolean`, `fan`, `siren`, and `humidifier`. Sensor `unit` and `device_class` can be null. Failed Home Assistant requests return `ok: false` and `error`.

### Detect sensors

Required POST fields: `command: detect_sensors` and string `entity_id`. Connection overrides are optional. The entity need not already be saved.

```python
print(command("detect_sensors", entity_id="switch.printer_plug"))
```

```json
{"ok": true, "power_sensor": "sensor.printer_plug_power", "energy_sensor": "sensor.printer_plug_energy"}
```

Either sensor field is null when no candidate matches. A lookup failure returns `ok: false` and `error`. Matching rules are in [Energy tracking](energy.md#attach-sensors).

## Energy history

POST body: `{"command": "energy_history"}`. Requires plug-control permission, even though it is a read operation. No parameters.

```python
print(command("energy_history"))
```

With no completed measurements:

```json
{"ok": true, "history": []}
```

Otherwise `history` contains up to 25 newest-first records with `name` (string), `outcome` (`done`, `failed`, or `cancelled`), `started` and `finished` (Unix seconds), and `kwh` (number). GET's `energy.last` contains the newest record or null. There is no pagination, delete-history command, or stored cost field.

## Plugin messages

The browser receives messages under plugin ID `homeassistant_power` through OctoPrint's plugin-message channel.

| `type` | Contents |
| --- | --- |
| `states` | The GET snapshot plus `type`. |
| `autooff` | `state`, `entity_id`, `trigger`, `seconds_remaining`, `detail`. |
| `poweron` | `state`: `connecting`, `connected`, `timeout`, `done`, or `failed`; failure can include `error`. |
| `print_energy` | Completed `record` with the history fields described above. |

## Home Assistant API consumed

The client authenticates with `Authorization: Bearer ...` and JSON. These are the only REST routes used by the plugin. See the authoritative [Home Assistant REST API reference](https://developers.home-assistant.io/docs/api/rest/) for the full state-object contract.

| Method and path | Plugin use | Request example | Response shape |
| --- | --- | --- | --- |
| `GET /api/` | Connection test | No body. | `{"message": "API running."}` |
| `GET /api/states` | Polling, discovery, detection | No body. | Array of state objects with `entity_id`, `state`, and `attributes`. |
| `GET /api/states/sensor.printer_plug_energy` | Fresh print-boundary meter reading | No body. | One state object, for example state `"18.41"` and `unit_of_measurement: kWh`. |
| `POST /api/services/switch/turn_on` | Turn a switch on | `{"entity_id": "switch.printer_plug"}` | Array of changed states. |
| `POST /api/services/switch/turn_off` | Turn a switch off | `{"entity_id": "switch.printer_plug"}` | Array of changed states. |

The service domain varies by entity. The client maps Home Assistant HTTP 401, 403, 404, other HTTP errors, TLS failures, timeouts, and non-JSON responses into `HomeAssistantError`. Those errors become the plugin JSON errors described above; upstream status codes are not forwarded as plugin HTTP status codes.
